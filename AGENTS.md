# My Coding and Development Rules

## 1. One Task at a Time

* Only implement the specific task I request.
* Do not implement additional features without my permission.
* Do not combine multiple development tasks into one change.
* If I request a single feature, complete only that feature.

## 2. Keep Changes Small

* Modify the minimum number of files necessary.
* Do not rewrite existing code unless it is necessary for the requested task.
* Do not refactor unrelated code.
* Do not rename files, variables, functions, or folders unless requested or necessary for the task.
* Do not install new packages without asking me first.

## 3. Explain Before Implementing

* First, inspect the relevant code and explain your proposed changes.
* Tell me which files you intend to modify and why.
* Wait for my approval before making changes.
* If the task is ambiguous, ask me a question instead of making assumptions.

## 4. Help Me Learn

* I am learning web development and the MERN stack.
* Prefer beginner-friendly, readable code over unnecessarily complex solutions.
* Follow the existing coding style and project structure.
* Do not introduce advanced patterns or abstractions without explaining their purpose.
* Do not replace understandable code with shorter but harder-to-understand code.

## 5. Explain Every Change

After implementing the approved task, explain:

* What changed.
* Which files were modified.
* Why each change was necessary.
* How the code works.
* Any new JavaScript, React, Node.js, Express, or MongoDB concepts introduced.

## 6. Testing and Safety

* Run only relevant, safe tests for the requested task.
* Never delete project files or existing functionality without permission.
* Never change environment variables, credentials, deployment settings, or database data unless explicitly authorized.
* Never commit or push code to GitHub without my permission.
* Never claim that a test passed unless it was actually executed successfully.

## 7. Final Report

After each task, provide:

1. The requested change implemented.
2. Files modified.
3. A simple explanation of the implementation.
4. Tests performed and their results.
5. Any issues or limitations.

## 8. Stop After Each Task

* After completing the requested task, stop.
* Do not start the next feature automatically.
* Wait for my instructions before proceeding.
